# Material and cutting actions

Use fresh RGB to identify the tool. A sprayer, atomizer, or vacuum must be switched on before use. One convenient sequence is to select a visible point on the tool's body and call `act(toggle_on)` while your hand is empty, then grasp it. You may also toggle the same tool you are currently carrying by selecting its visible body in the latest RGB; toggling a different object requires an empty hand. If the body is too small to locate confidently, navigate to a better view first. A point on grass, floor, or nearby furniture does not select the tool. While carrying the ready tool, choose a visible point on the target. `wipe` removes material with a compatible contact cleaner; `sweep` requires a broom; `vacuum` requires a vacuum. `spray` applies material from a ready atomizer or sprayer; `spread` transfers material already absorbed by the held tool. The executor checks the tool's current simulator abilities and material conditions, and verifies the selected target's material state after the action. If a tool is empty, switched off, or incompatible, change its state or tool instead of repeating the same request at other target pixels.

After a successful `toggle_on` on the actual tool, use the next RGB to select its visible body and call `grasp` if it is within reach. Grasp never navigates or turns the base. If it returns `out_of_reach`, explicitly call `navigate_to` to approach, then reselect the tool in the returned RGB. If repeated navigation to the tool is unhelpful, inspect from another visible landmark or viewpoint; floor pixels do not specify exact base positions.

A successful `toggle_on` confirms only that the selected object was switchable; it does not identify the object as the intended tool. Visually match the same tool before grasping. In a garden, a tall fixed light post with a colored cap can be switched on but is not a small handheld atomizer on the ground. If `spray` then reports a precondition error, recheck whether the object actually grasped was the one switched on; do not keep retrying different plants with an unready tool.

If `toggle_on` failed on a point that selected floor or another object, that failure says nothing about the sprayer. If you subsequently grasped the sprayer while it was still off, select the same held sprayer's visible body in the latest RGB and call `toggle_on`, then retry `spray` on the target. If its body cannot be selected while held, place it on a suitable surface, locate it in the returned RGB, toggle it on while empty-handed, and grasp the same sprayer again. Do not finish blocked immediately after putting down a potentially usable tool.

For a tiny handheld tool, a colored cap or dark tip at the bottom edge is not enough to identify its graspable body. If the item is clipped or occupies only a few pixels, change viewpoint or back away until the whole tool is visible, then select a point near the center of its body. A `fixed_object` grasp result means the executor resolved the target to a fixed object; inspect the returned RGB before retrying instead of clicking the same edge again. A `particle_target` result means the selected surface is loose material that cannot be grasped directly. Select a visible container or a suitable tool; do not repeat grasp on the particles.

For `soak`, carry an absorbent tool and select the visible fluid source or fluid-filled container. For `cut`, carry a slicer and select the visible sliceable or diceable object. These actions can alter or replace scene objects, so inspect the returned RGB before continuing. Use `hang` when the instruction is to hang a held object on a visible compatible nail or hook; it uses the same attachment state as `attach`.

The selected pixel identifies the only target. Material actions can change the target's whole simulator material state; they do not execute a physical sweep or spray trajectory. Treat action completion as evidence of that local state change, then check all task requirements before finishing.

For `spray`, keep track of which distinct visible targets returned a successful spray result. The coating may be hard to see in RGB even after the executor verifies the target's material state. Once every instructed target has a successful result and no other goal remains, call `finish(achieved)` using that feedback; repeated navigation toward already sprayed targets adds no verification.

For `cut`, one successful call applies one cutting transition to the selected object; it does not necessarily produce the form requested by the instruction. Inspect the returned RGB to assess whether the result is a whole item, halves or slices, or diced material. If further cutting is needed, select the relevant visible piece in the latest RGB while holding a compatible slicer; do not reuse the old target after an object is replaced. Stop when the observed result and action feedback support the requested form, rather than after a fixed number of calls or original items. Complete the remaining transfer, cleanup, and state requirements before finishing.
