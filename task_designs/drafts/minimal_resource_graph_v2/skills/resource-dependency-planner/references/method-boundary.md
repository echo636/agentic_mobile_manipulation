# Method boundary

The bundled modules preserve the evaluated R4 program: earlier R3 alternatives
plus macro graphs for material splits, loading, processing, shipment and resource
returns. Return nodes depend on the relevant resource's remaining uses. Graph
scheduling keeps both the completed-node set and the public action state,
including hand occupancy and retained contents. Only equal future states are
merged by cost.

Within the supported input range, the interface allows at most 1560 returned
method candidates. At most 56 added graphs have at most eight macro nodes each;
scheduling work is reported separately as expanded labels. The bound on returned
candidates is not a bound on all internal scheduling transitions.

Atomic shortest-path entry points in the shared research modules are disabled
by the CLI. Exact references used for evaluation were computed separately after
candidate generation or model responses finished.

On a frozen grid of 192 new same-family parameter configurations, R3 plus graph
scheduling matched 188 exact references, versus 158 for R3 and 160 for the graph
families alone. These methods are complementary. Four cases remained outside
the combined coverage. This is added program computation, not evidence that
graph representation alone or a text skill causes the improvement.

The interface returns a better model proposal unchanged and preserves it on
cost ties. Inspect `best_origin` before attributing a solution to the program.
The real CLI experiments used controller orchestration; packaging the same
program here does not establish autonomous tool discovery or native success.
