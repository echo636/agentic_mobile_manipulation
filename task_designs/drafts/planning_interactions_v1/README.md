## 最值得继续的完整任务

### 1. putting_away_games：分箱、装载与归位

原生目标是三件拼图同箱、三件桌游同另一箱、两类不能混装，最后两箱均进入书架。允许两箱身份互换。

- **需要看远的选择：** 箱子在什么时候、什么位置充当收集容器，什么时候完成最终归位。
- **可比较方案：** 先把空箱放书架再逐件装；在来源区域分类装箱再搬；一箱先完成，另一箱暂留可操作位置。
- **优势不一定成立的情况：** 当前理想抓放与自动接近若允许同样便利地装入书架内箱子，提前归位可能完全合理。纸箱搬运和可见性恢复也可能增加成本。
- **第一条物理验收链：** 三件物品装箱→实际携箱移动→书架内放置→逐件Inside保持。另验在架内直接装箱的替代路径。
- **等级：** 首选原生准入候选；同房间不等于无路线成本，也不冒称跨房间任务。

### 2. prepare_a_breakfast_bar：多来源、多级承托的早餐布置

厨房有果汁、华夫、点心、三个空餐盘和主托盘；餐厅已有两只煎饼。终态要求八件食物上餐盘，煎饼两件同盘、华夫两件同盘；不同组允许共盘。三个餐盘都须在主托盘或餐桌上，主托盘和果汁上桌。

- **需要看远的选择：** 哪些盘先去餐厅接已有食物，哪些留厨房集货；主托盘什么时候配送；是否利用原有装食物的承托物。
- **可比较方案：** 空盘/托盘先全部上桌再逐件送食物；按来源装盘后成组送；混合批次。三盘不必都挤上主托盘。
- **准入风险：** 公开知识库对部分食品的资产状态仍有缺口，本地实际资产尚未验证。不能凭任务存在就启动长回合。必须验证多层承托、来源柜内载盘抽取、每件可选与合法替代摆放。
- **等级：** 结构很适合；资产与承托验收优先于模型试跑。下方刚体换台草案提供更少新资产的替代设计，并非本任务成绩。

### 3. clean_up_after_a_dinner_party：跨房间分装与回运

餐厅有两汉堡、两卷饼和酒瓶；两个空盒在厨房柜里。两类食物分别同盒、盒入冰箱，酒也入冰箱。**原生目标没有关门要求**，不擅自添加。

- **需要看远的选择：** 搬食物去空盒，还是搬空盒去食物；送酒、取盒及盒载荷运输怎样交错。
- **关键反例：** 每盒仅两件，空手/取空盒的新增往返可能抵消成组回运的节省。必须计完整行程，不能只比较“装满盒后的一次回程”。
- **准入检查：** 两种合法盒子分配、两件食品载盒运输、不同访问顺序。含糊的容器身份不进入模型输入。
- **等级：** 跨区分装准入候选，规划收益有待实例证据。

### 4. unloading_shopping_items：两箱、多个目的地与渐进发现

两箱共十四件用品，分别放到console table和柜顶，两箱最终放在console table旁。源定义只有一个living room，不能推断跨房间。

- **需要看远的选择：** 按已发现的目的地安排箱子位置和卸货；是否过早归箱、逐件远送，或只检查了一层就结束。
- **信息条件必须另验：** 原生BDDL没有“不知道数量”的机制。只有当统一公开指令不泄露完整清单、部分内容初始确实不可见、且可通过合法动作逐步穷尽发现时，才能测新信息重规划。只隐藏物体却永远取不出来是坏场景。
- **风险：** 灯罩本地资产、十四件遮挡与目标可发现性，NextTo关系在后续动作中保持。
- **等级：** 发现/分流后备候选，不因为件数多就排为第一。

## 两份新增 BDDL：明确填补的缺口

### A. table_service_turnover：两人餐具换台与回收

[BDDL](table_service_turnover/problem0.bddl) · [中文指令](table_service_turnover/instruction.zh.txt) · [英文指令](table_service_turnover/instruction.en.txt) · [场景要求](table_service_turnover/scene_spec.json)

厨房台面两杯两盘送餐厅；餐厅原有两杯两盘回水槽；托盘最后进任一厨房柜，两柜关闭。允许新杯直接上桌或在任一新盘上。

**为什么新增：** 保留早餐/餐后服务的完整双向工作，减少依赖尚未核实的新食品资产、烹饪和粒子机制。与已有剩菜清台题不同，这里同时存在新餐具送出和旧餐具回收，托盘可双向使用；它不包含剩菜分装。

**自由度：** 可以逐件换台、先回收、先配送、混合往返，也可以不用托盘。没有“完整载托盘到达”历史目标，不强制先清空桌面。若托盘有收益，必须来自实际路径和装卸成本，而非评分拒绝逐件解。

**重点变体：** 远/近两房路径、不同托盘实际容量。公开来源描述与可辨认外观区分新旧餐具，不能靠作者实例ID；每件终态独立检查。

### B. two_zone_woodwork_and_cleanup：两处备柴、收纳与清扫

[BDDL](two_zone_woodwork_and_cleanup/problem0.bddl) · [中文指令](two_zone_woodwork_and_cleanup/instruction.zh.txt) · [英文指令](two_zone_woodwork_and_cleanup/instruction.en.txt) · [场景要求](two_zone_woodwork_and_cleanup/scene_spec.json)

车库和工具间各两根木料，全部劈成八段并收进任一箱，分配不限；两箱留在各自工作区，原有灰尘清除，斧头和扫帚归还工具间工具台。

**为什么新增：** 原生清洁任务中的抹布往往可以替代多种工具，不能自动提供严格两工具调度。这份草案复用官方 `chopping_wood` 和 `sweeping_garage` 的类型：斧头有切割能力，扫帚有材料移除能力，需要实际切换。八段是四根木料的真实产物，不用加大量重复物体凑动作数。

**保留真实自由度：** 先扫后切、分区完成、按工具分批、临时移动箱子、空箱携带工具都允许。当前切割不会自动生成本题灰尘；没有清空地面才能扫、上砧块才能切等额外门槛。

**用途限制：** 这是一项工具分组的机制对照。独立工作且工具共同初终位时，按工具巡回可由三角不等式弱支配逐区来回，距离变化不保证策略翻转。包括装箱/移动工具在内的完整策略成本须实际分析；不能单凭这个题宣布复杂场景自适应规划成立。

所有新定义均为 `custom_native_bddl`，`official_task_success=null`；没有加入当前模型任务注册/已构建目录。
