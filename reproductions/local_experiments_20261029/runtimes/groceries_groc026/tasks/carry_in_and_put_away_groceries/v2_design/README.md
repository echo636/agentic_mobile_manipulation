# 一体化扩展设计：两袋杂货入库

本目录是第二版任务定义及研究场景构建器。首版 `../` 只有一袋、两件食品，且真实回合在车库至厨房导航处失败。第二版不把清理旧餐食等独立家务拼进来；所有目标都来自同一次采购入库。

## 任务边界

车库后备箱中有两袋、六件食品。第一袋装番茄、牛奶和奶酪，第二袋装牛奶及两包饼干。两袋都要进入厨房；四件冷藏食品进冰箱，两包饼干进吊柜；空袋放冰箱旁，后备箱、冰箱、吊柜关好。[人类指令](instruction.txt)只描述终态，不规定搬运次序。

这比首版增加的不只是终态数量（首版 5 项，历史 v2 为 11 项，当前双柜定义每分支 12 项）：机器人需要处理两袋及两种收纳目的地，决定逐袋往返还是先集中搬运，再按存储条件分拣。冰箱关门依赖四件冷藏品入库，吊柜关门依赖两包饼干入库；空袋只有清空后才可最终放置。后备箱关门可在取出两袋后与室内工作交错。上述是作者侧因果关系，不向模型泄露路线。

## 落地门槛

[`problem0.bddl`](problem0.bddl) 是目标和初态定义，**不能仅靠 BDDL overlay 在公开实例 301 上运行**：公开场景只绑定一只纸袋、番茄和一盒牛奶。[`build_scene_overlay.py`](build_scene_overlay.py) 从固定来源构建研究用数据集叠加层，新增第二只袋、第二盒牛奶、奶酪、两包饼干及厨房吊柜绑定，公开数据保持原样。它已通过模拟器加载及绑定验证；新增物体的装袋初态、静置与暂放已有机制探针；2026-10-21 完整自主回合还完成了两只较高袋子的携物过门及六件逐件收纳。目标按自定义原生 BDDL 报告，不能称为公开挑战成绩。

后续复测的两次饼干 `grasp` 和 `place_inside` 均成功，但像素落点实际指向 `top_cabinet_tynnnw_1`，旧叠加层却把 BDDL 吊柜绑定到 `_0`，因此两个饼干目标被误判为失败。首次修正只把绑定改为 `_1`，仍未覆盖任一厨房吊柜都合理的语义；旧实验目录保留原始配置和评分。

**当前定义**同时绑定两个厨房吊柜，每包饼干可放入任一柜，也可分柜；两个柜都应关闭。BDDL 有 4 个替代分支，每分支 12 项原子目标，旧 11 项结果与其分开记录。当前构建器还将纸袋垂直尺寸调整为源实例的 1.2 倍，修复新增食品后番茄初始 Inside 为 false 的场景缺陷；保持食品大小和数量。`either_cabinet` 是原袋尺寸的历史叠加层，不能代表当前配置。真实模拟器已验证双柜分放后的原生整目标和开柜反例；这不是模型自主成功。当前版本、复现入口与收录门槛见[benchmark 候选卡](benchmark_card.md)。回归命令、根因、更正历史和复用条件统一记录在[修复日志 GROC-002](../../../docs/bugfix_journal.md#groc-002合理吊柜放置被错误评分)。

绑定修正后的完整 `gpt-6.1-sol / low` 回合为 **9/11，任务失败**：77 次 act/look 后模型报告 `achieved`，但第一盒牛奶与第二包饼干目标未满足。奶酪、番茄、第二盒牛奶和第一包饼干成功收纳，两袋归位，三处容器关闭。模型没有逐件核对袋内食品，把各类别已有一次成功当作全部完成。小件抓取并非普遍失败，后续应解决计数与清空验证；显式导航路径审计仍有未通过项。[实验记录](../../../../experiments/groceries_v2_cabinetfix_gpt61sol_low_20261020_r1/experiment_record.md)和[完整审阅页](http://10.130.140.115:8769/groceries_v2_cabinetfix_20261020_index.html)保留原始结果，不属于公开挑战成绩。

首轮 `gpt-6.1-sol / low` 视觉回合已经运行并失败：**3/11**，模型在车库门口通路反复受阻，未取袋。[实验记录](../../../../experiments/groceries_v2_gpt61sol_low_20261020_r2/experiment_record.md)和[内网审阅页](http://10.130.140.115:8769/groceries_v2_gpt61sol_low_20261020_index.html)保存原始证据与完整录像。该回合有操作动作内部路径，因此显式导航协议审计未通过。下一轮先解决车库至厨房路径和动作边界，再分别验证两袋过门、冷藏品入冰箱、饼干入吊柜、空袋放置和容器关门的视觉动作及独立谓词。首版与第二版不同定义，分数不能直接比较。

静态动作谓词覆盖检查为 `unsupported_predicates={}`；场景与实例加载通过。这些证据不证明装载物的物理关系、跨房间路径或完整任务动作可行。

## 车库门导航修复（2026-10-20）

首轮在门口反复折返有两个独立原因：模型选中的门内地板曾按“低矮物体”处理，规划终点被保持在距地板点约 1.4 米处；此外源场景默认的 `floor_trav_0.png` 把车库与门内区域分为不连通的两块，即使将侵蚀半径降到零也不连通。源场景另有 `floor_trav_open_door_0.png`。执行器现在对地板航点采用近距离终点，并且只在 `door_bexenl_0` 的原生 `Open` 状态为真时，把源开放门地图中这扇门附近的通行格加入运行时规划图；其他门和源数据不变。碰撞侵蚀及可移动家具遮罩仍在补图后执行。

[`probe_garage_door.py`](probe_garage_door.py) 使用首轮记录的门口起点与 RGB 点击所对应的地板世界点做**脚本化私有几何回归**，不计作模型成绩。修复后的真实模拟器探针到达门内 `[-2.90, 1.50]`，实际移动 1.74 米，终点误差低于 1 毫米；原始地图在同一点击点不连通。导航单元和适配器测试 40 项通过。

修复后的 `gpt-6.1-sol / low` 自主回合也成功多次穿门、往返车库并把两袋杂货带进厨房。[复测记录](../../../../experiments/groceries_v2_gpt61sol_low_doorfix_20261020_r3/experiment_record.md)和[内网审阅页](http://10.130.140.115:8769/groceries_v2_doorfix_20261020_index.html)保留轨迹及视频。模型服务在第 49 次动作后持续断流，未产生正式 `finish`；独立 BDDL **中间状态为 6/11，不是正式回合成绩**。门洞 bug 的修复已有真实行动证据，任务整体成功与显式导航协议仍未通过。

## 当前配置完整自主回归（2026-10-21）

`gpt-6.1-sol / low`、规划 skill 开启、无 demo，在双柜定义、袋高 ×1.2 和显式导航协议下取得 **12/12**，正式 `finish(achieved)`，全部协议与连续视频审计通过。105 次 act/look、13586 个 env.step，两只袋携物过门、六件逐件入库、空袋归位和关门均完成；所有导航路径来自模型显式 `navigate_to`。
