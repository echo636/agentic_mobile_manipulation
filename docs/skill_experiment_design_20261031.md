# 从行为缺陷到可归因的 skill 实验

> 研究方向更正（同日用户澄清）：主线是筛选和完成具有真实规划结构的长程任务。本文的关门、往返和清点短任务仅保留为诊断/回归手段，不作为主 benchmark 或主要贡献。长程选题标准与候选以 [长程规划任务筛选](long_horizon_planning_task_selection_20261031.md) 为准。

日期：2026-10-31。本文是实验设计建议，不是已实现的任务、已验证的策略收益或新实验结果。本次核对了现有任务/评分代码、skill、bug 日志及 2026-10-26 热饮配对报告；没有启动模拟器或模型实验。

建议把研究问题收窄为：**在固定、可执行的动作协议下，一种依赖公开观察的工作流 policy，能否更完整、更经济地完成家庭任务？** 先用短任务测清具体机制，再回到完整长程任务。首批只复用已验证的刚体、门和导航能力；布料、液体及复杂嵌套载荷继续作为独立设施开发对象。

## 2. 首批任务：每个任务只突出一个可解释的决策

以下是候选设计。资产、初态、动作链和评分完成验收后才能用于比较；不是已有可直接启动的任务。

### A. 取齐物品并恢复柜门：优先落地

人类目标示例：“把柜里的三件餐具送到桌上，完成后关好这个柜门。”使用一个已验证柜体、三个容易看清的刚体物品、一个开放目的台面。指令只定义结果，不规定先拿谁、什么时候关门。

主要决策：还有物品待取时是否保持入口可用；最后一件取出前是否安排空手关门；是否为了补关门额外往返、暂放和重新抓取。

候选 policy：打开任务相关柜门时记录恢复义务；明确最后一次访问；把关门放在满足取物需求且可空手执行的时机；结束前核对仍未消除的义务。不是每拿一件就关门，也不是忽略通路/遮挡一律开着。

主要指标：三件分别送达且门关闭的整任务成功、遗漏收尾率、为收尾新增的往返和重抓次数。开柜次数少本身不是成功。

变化与反例：柜门初态开/关、一次/多次取物、需要再次访问/已完成访问。初态开门时是否恢复原状由指令决定，不擅自要求全屋所有门关闭。门扇可能挡路的布局须单独验证，并允许提前关闭。

选择原因：直接对应截图中的收尾问题；不需要烧水、粒子、布料、食品嵌套或新载荷能力。还可暴露“计划里写了关门，但到最后忘记”的具体机制。

### B. 双向收送：先用单件携带测往返安排

人类目标示例：“把客厅两件用过的餐具送回厨房，同时把厨房的杯子和点心送到茶几。”先用可抓取的刚体，源区与目的区使用经验证的开放支撑面；不加入清洗或热饮状态。

主要决策：先做完所有送出再做所有收回，还是把返程用于带回已知物品。任务中的双向工作都服务于同一次餐后整理与重新摆台。

候选 policy：在跨区前比较接下来的完整往返，把已知、可执行且不违反依赖的返程载荷一起考虑；到目的区后先确认下一件待处理物和手状态，再决定是否返回。

主要指标：整任务成功、跨区次数、空手跨区次数、实际导航距离。模型只使用公开观察和自己见过的地标；离线距离或作者地图只用于分析。

变化与反例：起点互换、双向/单向需求、某个返程对象尚不可发现或暂不可取。探索与必要空手移动应保留，不机械地惩罚全部空手行走。

这项设计用单手已有能力就能产生路线差异，不必先解决托盘载荷。之后可增加“多件送往同一地点、托盘可用”的独立扩展。扩展要比较装载、卸载、取托盘、暂放与返程的总成本，并包含只有一件物品、托盘绕路等反例；不能把永远用托盘写成最优策略。

### C. 同类多件清点：把“全完成”变成可检验的义务

人类目标示例：“把桌上所有杯子收进收纳区。”先用开放台面上的 2–4 件同类物品，随后才加入可通过允许视角发现的局部遮挡。

主要决策：是否把一次类别成功当成整类完成；换视点后是否把同一件重复计数；重新规划时是否把“所有物品”收窄成“所有已看到的物品”。

候选 policy：维护逐件观察身份、最后可见位置、已尝试动作和完成证据；将搜索范围是否覆盖与已发现物品是否收完分开。身份不确定时保留不确定，不能使用模拟器实例 ID。整份计划替换仍须保留未知物品检查义务。

主要指标：逐件漏件率、错误完成声明率、整任务成功、确认成本。固定数量不在指令中时，不能把作者物品清单交给 policy。

变化与反例：件数、相似外观、可解除遮挡、视点改变；全部收完后也应能停止，不能用无休止搜索换取低错误声明率。

### D. 额外 navigate：作为低成本诊断用例

从“已可操作却先 navigate”的真实片段提取相同的公开历史和当前四路图像，比较下一动作选择。可见不等于可达；新视点可能影响选择、抓取和后续退出。

只有在可复现初态下，两条执行分支都验证后，才能确认该动作可删除且没有破坏后续链。否则只记为冗余候选。这适合做执行准备检查的小用例，不宜直接包装成整套长程规划贡献。

## 3. 怎样设计 skill，避免继续堆规则

按当前系统，先研究调用既有原子动作的高层闭环 policy。运动执行器、评分与 policy 分别冻结；模型仍决定动作和 RGB 像素。

每个候选 skill 应能明确回答五件事：

| 项目 | 例子 |
| --- | --- |
| 何时触发 | 即将跨区、即将打开容器、即将替换计划、即将结束 |
| 需要哪些公开状态 | 已见物品、手里是什么、门状态、未完成义务、位置不确定性 |
| 比较哪些行动 | 当前操作/重新接近；单件往返/返程带物；现在收尾/处理完同批再收尾 |
| 依据什么反馈更新 | 动作结果、当前 RGB、公开 grasp 类别；工具成功不能覆盖整类目标 |
| 何时退出或恢复 | 局部后置条件成立；否则获取新证据、改变站位或保留未决义务 |

首个候选只实现 A 的收尾义务与最后访问判断，复用现有计划/记忆能力。先检查现有规则为何没有落实，再重写触发与状态表述；不把 A/B/C 全塞进同一版。

若以后将状态维护做成结构化工具，它只能保存模型从公开证据提交的内容。自动识别对象、写入私有清单、替模型关门或自动选择路线都会改变实验条件，应另立实验，而不是算作 skill 文本收益。

建议把有效性的主张写成条件性的：“在多次取物并要求恢复柜门的任务中，减少遗漏与补救成本。”它比“让机器人更聪明”更容易验证，也能迁移到冰箱、抽屉、设备开关等同构义务。迁移对象仍须单独通过执行验收。

## 4. 用三级迭代降低成本

**第一级：离线公开历史用例。** 从已有回合收集最后取物、返程、同类第二件、错误类别反馈、临近结束等决策点。固定同样的任务指令、公开历史、四路图像和工具反馈，检查候选是否保持义务、是否选了可接受的下一步。允许多个合理动作，不用某一历史动作作唯一标准。这里验证决策与接口，不产生机器人自主成功率，也不能证明物理上少走了路。

**第二级：短闭环任务。** 在可重建初态中实际执行 A/B/C，发现动作与观测问题。设计目标是让多数开发回合在约 10–30 次动作内暴露核心决策；具体预算通过可行性检查后确定。局部 RGB、失败前后状态和独立终态评估仍保留，开发阶段不必每轮手工制作发布网页。

**第三级：完整任务与留出。** 只有候选在短任务上显示机制收益，才投入完整热饮/杂货等长任务，检查组合后是否还成立。完整运行继续使用规定的录像、配置与审计要求。

检查点不是默认捷径：GROC-012 已记录 sim 状态加部分 carry 恢复无法等价重现物理后续。离线重放公开历史可以先做；物理分叉要么从可验证的新初态启动，要么重放已验证前缀。只有恢复后的对象、手、门、接触/粒子状态及下一动作结果通过适用范围内的等价检查，才用于相应续跑，不能称全场景通用恢复。

## 5. 把 bug 日志变成一次性投入，而不是每轮人工通读

不要求先修完日志中的所有问题。只为首批任务所用能力选定一个冻结 runtime，维护小范围的准入证据。已有历史不重写，新问题保留失败证据并补对应检查。

| 短动作链 | 提前拦截的问题 |
| --- | --- |
| 同一可见目标 navigate → grasp | GROC-007/010：导航目标分类、到位后仍可见且可操作 |
| open → 携物通过 → 返回 | GROC-001：门状态与路径地图失配 |
| place → 退出 → close → 复查终态 | GROC-003/012：暂放挡路、关门后关系变化 |
| 合法目的地正例与漏件/未关门反例 | GROC-002：指令接受集合与评分不一致 |
| 实际线上工具 schema → 本地校验 → 错误恢复 | GROC-022：目录有必填字段但线上调用漏参 |
| 代表性动作序列持续推进并使用实际渲染节奏 | PARTY-020/021：局部链通过但长回合或实际视频路径不稳定 |

这不是新增一套通用框架。复用现有 runner、audit、`analyze_workflow_efficiency.py` 与冻结清单，把常用配置收成一个任务规格和一个运行入口，自动产出：版本、初态检查、是否启动成功、独立评分、成本、失败分类和证据位置。按资产/协议变化重跑受影响检查，避免每改一句 skill 都重新验收所有设施。

每次失败先分两类工作：

- 已确认的加载、协议、地图或评分缺陷：生成最小复现并在设施版本修复；该批策略比较按事先规则标注受影响范围。
- 环境可执行时的漏件、错误对象、无证据完成或低效动作：保留为 policy 结果。单次 unreachable/out_of_reach 还不足以确定是哪一类。

服务/仿真中断、初态失败和有效模型失败分别列出，并保留所有尝试。中途失效的回合保留已发生动作和缺失终态，不能用前缀分数冒充完整模型成绩。补跑规则事先固定，不能按好坏成绩补抽。

## 6. 最小对照与晋级条件

首批只做任务 A 的开发 pilot，建议 3 个初态条件 × 2 次重复 × 2 组 = 12 回合。数量是用于发现机制问题的成本上限建议，不是统计充分性保证。先完成设施准入，再冻结具体配置；本次未启动这些回合。

两组共有基础操作 skills、工具、memory 接口、decision schema、模型/档位、预算、结束监督和评分；只改变目标策略文档。无候选组仍使用相同工具可用性，实际使用量计入成本。现有“长程文档＋三工具＋active_subgoal”组合对照可保留为整体系统对照，但不能据它单独归因文档收益。

按初态配对并平衡执行顺序，保留全部尝试。重复 seed 不等于独立布局。候选晋级后，再加入一句“取完记得关门”的简单提醒对照，检验收益是否需要结构化 policy；留出配置在选版前冻结，使用其结果调策略后转为开发数据。

预先指定：

1. 首要指标是所有要求同时成立的成功率、漏件和遗漏收尾；不要把初态就关闭的门当作新增进展。
2. 经济性报告跨区/空手往返、真实路径、动作、工具耗时、推理/传输等待与模拟步；时间不能只看一次共享主机墙钟。
3. 成功率与成本并列。成本配对解释可优先看双方均成功的相同条件，但必须同时公布全部成功/失败与未完成成本，避免幸存者偏差。
4. 若使用相对参考路径的额外成本，参考只能称“已验证可行方案”；未证明最优就不能称最优 regret。
5. 一条没有稳定触发的规则、只在一个录像里好看的轨迹，或少走几步但漏一件，均不足以晋级。

如果 baseline 本来就稳定完成任务 A 且成本相当，这是有价值的负结果：收尾不是此配置下的主要能力缺口。应转向 B 或 C 已有失败证据对应的机制，而不是调整任务直到偏好某个 policy。

## 7. 寻找现成任务的具体入口

优先找已安装、关键链验证过的实例；“知识库有任务名”或“有 BDDL”不代表本机可直接运行。以下本地定义已核对，场景/资产可用性本次未做验证：

| 本地 BEHAVIOR 定义 | 可借用的能力 | 新增风险与使用建议 |
| --- | --- | --- |
| putting_dirty_dishes_in_sink | 两碗两盘逐件收集，适合 C 的任务语义 | 初态含污物/污渍，不能仅看终态简单就假设无粒子成本；先查已有实例 |
| putting_away_toys | 多件核查、多个合法收纳箱 | 原定义八件且有地面物体；初期可用公开台面的自定义缩小变体，明确另立版本 |
| clearing_food_from_table_into_fridge | 食物装盒、冷藏与明确关冰箱 | 原定义含嵌套 Inside，适合后续组合验证，首轮不必承担这条高风险链 |
| setting_the_table | 多对象配对与摆放 | 当前日志 TABLE-001 已记录配对采样问题，不列为首批省事候选 |

本地定义根：`../../behavior_challenge_sunyujie/BEHAVIOR-1K/bddl3/bddl/activity_definitions/`。现有 [清台与剩菜任务](../tasks/clear_dinner_and_store_leftovers/README.md) 仍为设计候选，不能当作已有成熟任务直接扩展。

外部方法参照：LIBERO 原论文将空间、对象和目标变化拆成不同套件，再测试长程迁移（arXiv:2306.03310）。这里借用“分因素变化与留出”的设计思想，不建议为本轮实验迁移模拟器。BEHAVIOR-1K 原论文（arXiv:2403.09227）可用于查任务语义；本项目真实可执行性仍以本地版本和探针为准。

建议的第一项交付是 **一个可重复的取物收尾任务 + 一个聚焦候选 policy + 一个自动结果表**。先用它打通低成本的设计、执行和归因，再扩到往返安排、逐件清点与完整长任务。
