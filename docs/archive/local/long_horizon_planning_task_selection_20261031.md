# 按规划结构筛选长程具身任务

2026-10-31。用户澄清后的研究主线：从有真实因果依赖、资源约束和跨分支协调的完整家庭任务出发，设计通用长程规划 skill，使用同一组原子动作完成任务。短任务只服务于设施诊断与机制定位，不能替代完整长程任务的证据。

本次完成任务定义、动作实现与原始资料审阅；没有运行新模拟器回合，没有宣称任何新任务已通过执行准入。图片中的“首次”是研究设想，本次不作优先权/新颖性认定。

## 1. 选题标准：一个规划决策会怎样改变后面的可行性或成本

长轨迹可以来自重复搬物、低成功率抓取或不断找物，不自动构成长程规划证据。强候选至少包含一条多阶段因果链，并在某处需要考虑未来义务、共享资源、其他分支或结果保持。每个候选都必须写出以下四件事：

1. **必须满足的前置条件。** 哪个动作没有前一步就做不了？证据应来自原子动作/状态转移实现或实际可行性验证，不从任务名字或人类常识猜测。
2. **至少两个可区分的执行选择。** 如逐罐完成或批量准备、先装后搬或先搬后装、先做哪个材料分支、什么时候腾手和收尾。不能仅列一条固定长流程。
3. **错误选择的具体后果。** 不满足目标、产生禁止状态、破坏已完成关系、反复重开/重抓、额外跨区或工具准备。区分不可恢复失败与仍可完成但代价更大的方案。
4. **能被评测捕获的差别。** 全部目标是否同时成立、完成过程中是否发生目标退化、额外路径/重抓/切换、独立终态。单看DAG节点数或是否调用update_plan不证明规划有用。

“必须规划”不等于“必须使用显式DAG或我们的skill”。模型可能在普通提示下隐式规划。实验要验证候选是否提高这些规划决策的可靠性和成本表现，不能预设无skill组一定失败。

筛选还要将**规划价值**与**执行准入**分开记录：前者看依赖、资源和错误选择后果，后者看同一动作协议下的资产、可观测性、关键链和评分。高规划价值但关键链未验证的任务仍是研究候选；已经可运行但仅重复搬物的任务可作对照。

将证据分成两类：

- **成功所需的规划：** 目标存在真实前置、互斥或保持要求；遗漏它们无法达到完整终态。
- **效率所需的规划：** 许多顺序都可完成，但路线、准备、工具与暂放成本不同。

二者都契合用户图中的“完成/高效完成”，但报告不能互相代替。

## 3. 以这些完整任务为主线

### A. can_meat：两罐肉类分装与归柜——优先检查的刚体候选

官方任务：从柜中取两只带盖罐，将四根已经煮熟的香肠每罐装两根，关罐盖，放回柜子并关柜门。

**规划结构：** 两条分装分支共享一只手、工作台和外层柜；每条都有“入口可用→计数分配→完成装载→关闭→归柜”的依赖，最终还要合并到外层关闭。执行器规定操作另一物体的门须空手，且不能放入关闭的可开合容器，因此拿着香肠才发现罐子没开，会产生真实的暂放/腾手依赖。过早关罐/关柜则需要重开。

**skill 应做的事：** 保留每个罐子的装载义务与数量；比较逐罐完成和成组准备的成本；在最后一次使用前维持访问条件；安排好内外两层收尾，避免用“罐子已归柜”覆盖“内容已经齐全”。

**为什么优先：** 无须新增烹饪，香肠初态已cooked；相比切碎、配方和清洁任务，少一类材料状态机制。规划结构与门/容器/持物契约直接相关。仓库demo_reliability记录了历史can-meat r30一次自主审计通过，可复用其路径证据；不能把旧配置的一次成功当成当前版本的重复性验收。

**不能先假定的事：** 不能断言所有实例都必须取出罐子才能装，或某种批处理顺序必然更省。必须验证罐盖操作、口径、两根容纳、载荷运输和关盖后Inside保持。BDDL未明示的初始开合状态以实际实例为准；本地`NQuantifier.evaluate`已核实采用`sum(child_values) == N`，故`forn(2)`确为恰好2；实际物理容纳与当前实例可达性仍待验证。

### B. canning_food：两类食物加工、隔离分装与收纳——强因果规划候选

官方任务：从冰箱取牛排和菠萝，取得两只碗，用刀切碎，两种材料各装一碗且不能混在一起，最后两碗入柜，关冰箱和柜门。

**规划结构：** 两条“原料→切碎后的材料→单独装碗→归柜”分支，共用刀和工作区，并有禁止混装的负目标。完成一个分支时需要保护另一个分支的容器和材料身份；切碎会改变对象表示，不能继续按原来的整块物体清单记账。

**直接评分证据：** BDDL要求两种diced材料real；分别存在filled目标碗，并对另一种材料要求not contains；两碗均Inside柜且两处门关闭。这里的“不要混”是真实目标约束。

**skill 应做的事：** 在不可逆加工前确定容器分配与后续材料去向；以公开反馈更新“整物→材料”状态；围绕工具占手安排准备和搬运；将防混装条件保留为执行中约束，不能只在最后计数。

**执行风险：** 切碎生成粒子，随后收集/倒入/运输必须真实可执行。当前cut动作只验证切割工具和目标能力，并不要求目标一定在砧板上；不能把“先放砧板”伪装成执行器强制依赖。BDDL和静态动作表不能证明完整材料链已经跑通。该任务规划价值高，准入成本也较高。

### C. prepare_and_serve_hot_drink：复用现有完整任务研究分支协调

这是本项目自建任务，不是官方100之一。水源、装水、加热、倒入杯中、送达是一条因果链；餐具、点心和承托物构成其他分支，在服务目标汇合。

**应测的规划：** 单手资源和器具准备、多个分支的交错、成组运输是否值得、未找到必要物品时如何保持该义务、什么时候形成完整配送批次。早送一个物品可能局部有进展，却增加后续往返；无托盘或托盘不划算时又不能机械成组。

**本项目需诚实限定的部分：** 当前常用的是11项高层热饮评分，不等于原生粒子任务；关门不是当前11项目标。作者侧partial_order中存在摆台/点心等先后关系，但它没有用于当前正式高层评分；不能将作者画出的全部箭头说成环境强制依赖。若要测加热等待与其他分支并行，须先核实boil是否异步、仿真时间如何推进，不能仅凭日常常识声称可利用等待期。

现有完整任务已有轨迹，因此适合作为首批连续研究对象；先明确到底测因果完成、运输调度还是逐件完成，不再一轮同时修改场景、执行器和skill。

### D. make_pizza：汇合与配方规划——先排除任务捷径

官方说明包含取多种原料、切洋葱和蘑菇、汇合到饼底、入炉转化成披萨，是很强的多分支汇合设计。

但是本地BDDL终态只有real(pizza)和OnTop(pizza, cookie_sheet)，并不逐项要求所有配料。真正需要哪些原料由实际激活的转移配方决定；源码审阅发现存在simple_pizza路径。因此“看起来有很多配料”还不足以证明所有分支都是完成任务必需的。

准入前要检查实际对象范围、配方匹配、输入数量/材料条件、产物和评分，测试省略某配料是否仍可成功。若较短合法方案存在，就据实定义测量范围；若修改配方或增加条件，标为自定义版本，不沿用官方任务结论。该候选保留为上限挑战，不作为立刻可运行的主实验承诺。

### E. clean_your_house_after_a_wild_party：工具与区域协调的后续长任务

属于完整BDDL库中的研究任务，本地官方100没有它。现有研究实例包含餐具/回收收纳和多个房间的不同清洁义务。

其价值在于按材料和工具准备条件组织工作，再结合房间路线，而不是只按最近物体行动。当前日志中干毛巾不能直接完成某些清洁、工具需浸湿/吸收材料后再用，提供了可研究的真实前置证据；不能把不同表面、不同污物都归成同一种wipe。

近期r64的232动作、11/14终态是有用的部分任务证据，但浴室接近和其余目标链仍需验证。将它保留为复杂综合任务，当前不据此声称设施成熟、完整成功或规划收益成立。已做的工程工作仍有价值，但不让未定位设施问题承担首个规划收益结论。

### F. cook_cabbage：相同加工能力、相反的产物组织要求

官方任务的两个目标产物是cooked-diced cabbage和cooked-diced chili，最终都在同一口锅内。它与canning_food可形成有解释力的迁移组合：一个要求两类产物隔离，另一个要求汇合。skill必须根据最终关系和当前状态安排接料、刀具与锅，不能硬编码“一律分开”或“一律合批”。

这是完整任务之间的机制迁移，不是只换物体名字。目标未强制先切再煮；原生切碎转换能够保留cooked属性，须按实际合法方法设计计划。两任务共用切割/粒子设施，但加热链须额外验收。

### 支持任务与排除项

- `loading_the_car`：相机入箱、箱和球拍跨房间入车，适合运输前打包、载荷保持和访问准备的迁移检查；对象少，单独作为主要长程规划证据偏弱。本地原BDDL把关车门放在and块之外；实际parser只返回三个Inside目标，关车门未进入其目标列表。因此该评分缺口须先处理或明确限定，不能只看指令认定终态已经覆盖。
- `cleaning_up_plates_and_food`：双盘食物冷藏与碗入水槽有分流、载荷和关门义务。说明要求保持各自盘上，但终态forpairs不强制沿全过程保持原配对，不能把它当作已评分的过程约束。
- `assembling_gift_baskets`：四篮各一件四类物品，适合分配与逐件记忆，因果深度较浅；可作对照或迁移，不因为需要很多次抓放就排为主候选。
- 单件取物关门、单纯多件搬运、仅扩大房间距离：作为设施检查或效率子用例；不替代上述完整任务。

## 4. 首批选择与研究节奏

优先从**can_meat**复用历史执行证据，进入完整嵌套装载任务；以**canning_food → cook_cabbage**形成“产物隔离 → 产物汇合”的官方任务迁移组合。已有完整热饮保留为多分支服务的综合验证。make_pizza在排除配方捷径后加入；party继续作为后续综合任务。这个顺序依据规划结构与执行准入证据，不按任务名或录像长度排序。

顺序上先审清“目标→允许方法→真实前置→执行链”，随后只对入选候选验证尚未被证实的关键链。若某候选硬机制暂不可行，保留为规划候选并修对应设施或选择同构任务；不能用模型跑不通直接判定规划能力差，也不能通过去掉关键依赖让它更容易成功。

长程任务从完整初态执行到独立终态，是主结果。短前缀/片段/私有探针只用于确认关键动作和定位策略，不能替代主结果。

## 5. 图与优化目标：优化执行方案，不优化节点少或边少

图片中“构建最小图 / DAG能量函数”可以进一步明确：

- 任务目标与约束决定必须完成什么。
- 方法选择决定用什么链达到目标，存在替代方法时需要AND/OR结构。
- 部分有序的事件计划表达真正的因果先后；不要人为串行化所有目标。
- 机器人手、工具状态、位置、可访问容器和暂放空间是资源/状态条件。
- 开关门、回访和恢复会反复出现；它们是不同执行事件，静态目标DAG本身无法完整表示。

先构建可行计划，再比较实际执行轨迹的代价。设计性目标可写为：

`在全部目标与约束得到满足的可行计划中，最小化期望的行走、操作、工具准备/切换和恢复成本。`

实现上可用滚动的短窗口比较，先只比较下一组可执行分支。距离和风险估计来自公开观察与已经执行过的路线，不将作者地图、物体坐标和隐藏评分输入policy。权重及预算在开发数据上固定；成功与失败在评测中单列，不能通过高权重奖励“少动”让提前放弃变优。

DAG顶点数不等于成本：同一DAG可有不同执行顺序、不同路线和不同工具切换次数；加一条“提前准备容器”的动作可能降低总成本。先做DAG与资源/执行成本的清晰定义，再决定是否值得实现更复杂的图优化。

## 6. 从这些任务提炼的通用skill

统一策略可以围绕同一套闭环组织，而不写任务固定脚本：

1. 从目标倒推准备条件与必须保持的约束，区分逐件义务、材料状态和最终恢复义务。
2. 保留可选方法和真正独立的分支，避免把所有搬运完成设成处理第一件的假前提。
3. 做未来会占手、封闭入口、改变材料或破坏可逆性的操作前，检查后续链是否已准备好。
4. 从当前可执行分支中比较一段完整工作量，包含准备、取放、暂放、返程和收尾，而不只比较下一动作距离。
5. 动作后以公开证据更新状态；改变形态、身份不确定或目标关系可能丢失时重新核验。
6. 失败时修订受影响分支，同时保留其他未解决义务；完成时检查全部目标共同成立。

要显示这是“规划”贡献，可在固定动作执行器、观察、工具与模型下，先比较现有基线和完整候选。在有代表性的完整任务上再做机制消融：仅目标清单、清单+真实依赖、加入资源与代价调度。比较范围和新增工具分开写清，保留失败。不要一次铺开所有消融，先从已有普通回合找出具体决策差异。

官方不少人类instruction已经提供操作顺序。若保持官方输入，就明确研究的是遵循长依赖、状态保持和执行优化；若要研究自主生成分解，另立双方一致的“只给目标与约束”的输入版本，不能把删掉步骤的效果混进skill增益。

所有候选的第一张证据表都应回答：**这个任务里，哪一个选择需要看得更远；哪个真实约束使这个选择重要；我们的策略如何改变它；独立结果是否支持。**
